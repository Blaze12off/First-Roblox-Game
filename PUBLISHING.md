# Обновление существующего плейса

## Проверенный способ — 15 октября 2026

1. Сохранить локальный `SimulatorMVP-EdgeHUD.rbxl` и исходники.
2. В Studio открыть **File → Open from Roblox → TEST**. Нужна именно облачная вкладка с названием TEST, а не локальный `.rbxl`.
3. Внести изменения в эту вкладку. Чтобы перенести текущие исходники репозитория, выполнить `./tools/PrepareCloudSync.ps1`, открыть полученный `tools/CloudSync.tmp`, скопировать его в Command Bar облачной вкладки и выполнить вне Play. Перед изменениями команда проверяет Place ID и Universe ID; посторонние объекты не удаляет.
4. Выбрать **File → Publish**. Save to Roblox сохраняет версию; Publish делает её опубликованной.
5. Проверить новую версию в [Version History](https://create.roblox.com/dashboard/creations/experiences/10770928979/places/108052777594261/version-history), в том числе с фильтром Show published only.

Генератор переносит 26 игровых скриптов/модулей из `src`, включая конфигурацию. Он не переносит ручные правки геометрии в редакторе, сторонние ассеты, настройки доступа и данные игроков. Наш runtime-мир собирается из `World` и связанных модулей. Генератор сам не запускает Studio и ничего не публикует. Для другого плейса передать его `-PlaceId` и `-UniverseId` явно.

## Результат диагностики

- Experience: `10770928979`; стартовый Place: `108052777594261`.
- В старых логах 0.742 зависал путь **локальный файл с currentPlace=0/currentUniverse=0 → Publish As → существующий плейс**: после выбора назначения не начиналась стадия PublishInitiated. Создание новой experience проходило полностью. Это локализация проблемного пути, а не доказанная внутренняя причина ошибки Studio.
- В Studio 0.743 обычный Publish из открытого облачного TEST прошёл за **1576 мс**, появилась версия **6** (15.10.2026, 16:45 МСК).
- Затем в тот же облачный плейс перенесены все 26 игровых исходников коммита `2d90f4d` с точной проверкой Source. Следующий Publish прошёл за **1586 мс**, появилась версия **7** (15.10.2026, 16:48 МСК). Place ID и Universe ID не менялись.
- Общие TLS-ошибки телеметрии встречаются и при успешной публикации; связывать с ними зависание Publish As доказательств нет.
- Новую игру для каждого обновления создавать больше не требуется, пока работает проверенный путь через облачную вкладку. Удаление старых публикаций не выполнялось. Настройки доступа не изменялись. Повторный вход в обычном Roblox после этой публикации отдельно не проверялся.
