# Simulator MVP — сила и перерождения

Готовый локальный плейс: `SimulatorMVP.rbxlx` (настоящий XML place-файл Roblox, открывается напрямую в Studio).
Версия, сохранённая из Studio с новым распределённым интерфейсом: `SimulatorMVP-EdgeHUD.rbxl`. Сила и уровень находятся сверху слева, монеты сверху, магазин/награды слева, перерождения справа. Подробные панели открываются только кнопками; тренировка появляется снизу рядом со станцией.
Исходники и воспроизводимая сборка находятся рядом. Предыдущий PetObby не изменён.

## Тестовые яйца и питомцы

Две стойки слева от зелёной площадки: луговое яйцо за 80 монет (Кот 60%, Пёс 30%, Кролик 10%) и кристальное за 240 монет (20%, 45%, 35%). Подойдите к выбранной стойке, нажмите F или её экранную подсказку; меню также доступно через отдельную кнопку «Яйца и питомцы» на главном экране под «Наградами». Вкладки окна: «Выбор яйца», «Питомцы» и заглушка «Донатные предметы». Списки прокручиваются вертикально; карточки показывают изображение модели. Выбрать яйцо можно из каталога, а открыть — только рядом с соответствующей стойкой. У недоступного яйца скрывается описание и показан требуемый уровень. Оба тестовых яйца сейчас имеют MinLevel=0; будущие уровни пока не настроены. Это игровые монеты, покупки за Robux не добавлены.

Питомцы: Кот x1.10, Пёс x1.20, Кролик x1.35 к силе и монетам за тренировку. Множители в информации для игрока всегда записываются как x0.00; проценты используются только для шансов выпадения. Первого питомца игра экипирует автоматически; в меню можно заменить или снять его. Одновременно можно нанять до трёх обычных питомцев, включая имеющиеся дубликаты. В инвентаре максимум 50. Команда получает множитель 1 + сумма прибавок нанятых питомцев. Четвёртый слот только для будущего донатного питомца и сейчас недоступен. Простая 3D-модель движется вместе с персонажем. Питомцы и экипировка сохраняются через существующий профиль и не сбрасываются при перерождении. Старые профили версий 1 и 2 автоматически мигрируют в версию 3 с сохранением прежних полей и экипировки.

Списание монет, случайный результат, вместимость, расстояние, cooldown и наличие питомца проверяет сервер. Клиент не передаёт стоимость, шанс, результат или бонус. Проверка в Studio: запустите свежий sandbox Play и выполните `tests/PetsStudioQA.client.lua` в клиентской Command Bar. Скрипт проверяет открытие вдали/вблизи, списание, выдачу, повтор без монет, экипировку, модель и бонус. Для облачной проверки получите питомца в приватном плейсе, выйдите и войдите снова.

12 октября 2026 пользователь подтвердил, что существующий прогресс сохраняется после перезахода в обычном Roblox. Сохранение новых полей питомцев требует отдельного такого же теста после публикации обновления.

## Быстрый запуск

1. Остановить текущий Play. Roblox Studio → File → Open from File → `X:\GameDev\RobloxSimulator\SimulatorMVP.rbxlx`. Если этот файл уже открыт, закрыть его без сохранения старой версии и открыть заново: внешняя сборка не обновляет вкладку Studio автоматически.
2. Нажать Play. В Studio по умолчанию включён **sandbox без сохранений**, об этом написано в интерфейсе. Каждый новый Play начинает с нуля.
3. Подойти к зелёной станции. Нажимать E или кнопку «Тренироваться». Получать силу и монеты.
4. Открыть «Магазин» слева и купить улучшение за 25 монет. Следующие цены растут; уровень 3 открывает фиолетовую станцию с бонусом 25%.
5. Открыть «Перерождения» справа: там показаны требования и прогресс. Собрать силу и монеты, нажать «Переродиться…», прочитать сброс и подтвердить. Подтверждение одноразовое и действует 20 секунд.
6. Сила, монеты и уровень сбрасываются. Rebirth, суммарный рекорд, косметика и таймеры наград сохраняются. После первого Rebirth открывается бронзовая аура, после десятого — неоновый след.
7. После трёх тренировок доступны ежедневная и недельная награды. Они не требуют лайка, подписки или покупки. Пропуск дня ничего не сбрасывает.

## Настоящие сохранения и публикация

Sandbox — только удобство локальной разработки, НЕ имитация DataStore. При запуске в Roblox вне Studio сервер всегда использует настоящий DataStore, независимо от StudioOffline.

Для проверки между сессиями:

1. Создать отдельную приватную тестовую experience через File → Publish to Roblox (владелец выбирает название, доступ и заполняет необходимые настройки Creator Dashboard).
2. В File → Experience Settings → Security включить **Enable Studio Access to API Services** и сохранить. Это действие выполняет владелец. HTTP Requests и LoadString не нужны.
3. В ReplicatedStorage → SimulatorShared → Config поменять `StudioOffline = false`.
4. Опубликовать актуальную версию. В Studio используется `StrengthSimulator_STUDIO_v1`, вне Studio — `StrengthSimulator_v1`. Они разделены, но для тестов всё равно лучше отдельная experience.
5. Запустить Play, заработать прогресс, выйти через Stop, дождаться завершения сохранения, запустить снова. Должны загрузиться сила, монеты, уровень, Rebirth, рекорд, косметика и таймеры наград.
6. Аналогично проверить два последовательных входа через клиент Roblox. Реальная облачная проверка считается выполненной только после этого, а не после теста с поддельным backend.

Источник процедур: [официальная документация DataStore](https://create.roblox.com/docs/cloud-services/data-stores).


`src/shared`, `src/server`, `src/client` повторяют эту структуру. Источником изменений является код в `src`; place-файл — собранный снимок. Автоматической синхронизации с файлами нет.

После изменений выполнить `powershell -NoProfile -ExecutionPolicy Bypass -File X:\GameDev\RobloxSimulator\BuildPlace.ps1`, открыть заново новый `.rbxlx` и нажать Play. Карта и интерфейс создаются автоматически. Для просмотра полной карты с вывесками до Play можно в Command Bar **в режиме редактирования** выполнить:

```lua
require(game.ServerScriptService.Simulator.World).Build()
```

При желании File → Save As → новый `.rbxl`. Генератор пересоздаёт только `SimulatorMVP.rbxlx`. Геометрия в Workspace является предпросмотром: при каждом Play модуль World пересоздаёт её. Изменять расположение и оформление нужно в World/Config, иначе ручные изменения предпросмотра не попадут в игровой запуск.

## Защита данных и действий

- Клиент передаёт только название действия, ID станции/косметики или одноразовый токен. Суммы, множители, время и требования рассчитывает сервер.
- Token bucket: прочие действия — 8 запросов в пачке и 4/сек; тренировка — отдельные 64 в пачке и 32/сек. У тренировки нет игровой задержки между нажатиями, расстояние и награды проверяет сервер. У остальных действий сохраняются свои cooldown.
- Для тренировок проверяются точные аргументы, существование станции, живой персонаж, расстояние 11 studs и необходимый уровень. ProximityPrompt проходит тот же серверный диспетчер.
- Клиентские изменения HUD или leaderstats не меняют серверный профиль. Таблица игроков содержит серверные Rebirths и LifetimePower — суммарную силу за все циклы.
- Загрузка захватывает lease через UpdateAsync. Сохранения одного ключа сериализуются, используют свежий серверный снимок и проверяют владельца lease. Старый сервер после захвата другим не может перезаписать профиль.
- Дефолты создаются только при отсутствующем ключе. Ошибка чтения, чужой lock, неизвестная версия или повреждённые данные запрещают игру и запись дефолтов; игрок получает понятное сообщение.
- Автосохранение каждые 45 сек, обновление lease на 180 сек, сохранение при выходе и параллельное завершение через BindToClose. Ошибки повторяются ограниченно с backoff. При истечении lease действия прекращаются, игрок отключается.
- Ежедневная/недельная награда проверяется по серверному os.time и записывается в тот же профиль. Rebirth не сбрасывает таймеры. Выдача косметики идемпотентна.
- Никаких секретов, покупок Robux, внешних моделей с неизвестными скриптами, проверки лайков/подписок и административных ремоутов выдачи валюты.

Архитектура следует [рекомендациям о данных и session locking](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing) и [валидации клиентских действий](https://create.roblox.com/docs/scripting/security/client-server-boundary).

## Автоматические проверки

В режиме редактирования или в серверной Command Bar:

```lua
require(game.ServerScriptService.Simulator.Tests.Spec).Run()
```

Проверяет схему, NaN/Infinity, цены, недоступную зону, сброс Rebirth, сохранение остальных полей, косметику, временные границы наград, повторные выдачи, некорректные аргументы, ограничение частоты. Поддельный UpdateAsync проверяет реальную логику PlayerData: загрузку/сохранение/повторный вход, конфликт двух серверов, ошибки чтения/записи, повтор callback, потерянный ответ после commit, истечение lease, захват другим сервером и повреждённые записи. Живой DataStore этим не проверяется.

`tests/StudioIntegration.lua` — интеграционная проверка в свежем Play с `StudioOffline=true`. Открыть серверную Command Bar (переключатель Server) и выполнить:

```lua
require(game.ServerScriptService.Simulator.Tests.Integration).Run()
```

Тест около минуты зарабатывает прогресс обычными серверными действиями и проверяет дистанцию, аргументы, cooldown, покупку, награду, подтверждённый Rebirth, replay, косметику и возрождение. Тест не встроен в обычный игровой цикл и не работает в опубликованной игре. Во время теста не перемещать персонажа и не нажимать кнопки игрового интерфейса. Смотреть Output: ожидается `SIMULATOR_INTEGRATION_PASS`.

Локальная проверка без Studio: `powershell -NoProfile -ExecutionPolicy Bypass -File X:\GameDev\RobloxSimulator\tests\RunLocal.ps1`. В tools лежит официальный Luau CLI 0.741: архив получен из релиза luau-lang/luau и проверен по SHA256 из GitHub API. Скрипт компилирует все 16 исходников и запускает те же 81 проверки с минимальным адаптером Roblox-сервисов. Адаптер не доказывает работу физики, GUI, сетевого транспорта и облачного DataStore.

## Ручная приёмка

- Новый игрок: понятная инструкция, E и экранная кнопка работают только рядом с тренером, первый апгрейд доступен после четырёх тренировок.
- Нажать быстро E/кнопку много раз: выдача ограничена. Отойти и попробовать через клиентскую Command Bar `game.ReplicatedStorage.SimulatorRemotes.Action:FireServer("Train", "Basic")`: награды издалека нет.
- Попробовать `FireServer("Train", "Basic", 1000000)` и `FireServer("Coins", 1000000)`: сервер ничего не выдаёт.
- До уровня 3 фиолетовая станция не работает, после уровня 3 даёт повышенную награду.
- Rebirth: до условий отказ; отмена ничего не сбрасывает; подтверждение сбрасывает ровно три поля. Повтор старого токена и истёкшее подтверждение не работают.
- Получить обе награды, повторить запросы и зайти снова с настоящим DataStore: повторной выдачи до сроков нет.
- После первого Rebirth выключить/включить ауру, умереть: Rebirth и выбранная косметика сохраняются.
- В Studio Server & Clients с двумя игроками проверить независимость валюты, таймеров и подтверждений и сравнение в таблице игроков.
- Проверить UI на узком экране, мышью, E и касаниями на мобильном эмуляторе.
- В отдельном тестовом плейсе с отключёнными API и `StudioOffline=false` загрузка должна отказать, а не дать сохраняемые дефолты. После восстановления API прежний профиль должен остаться.

## Интерфейс Glass HUD (10 октября 2026)

Плейс с новым HUD: `SimulatorMVP-EdgeHUD.rbxl`; открывается в Studio, запуск — F5. Полная сборка из исходников — `SimulatorMVP.rbxlx` через `BuildPlace.ps1`.

Общий стиль находится в `src/client/Glass.lua`: полупрозрачные поверхности, мягкий градиент, тонкие границы, световой блик, геометрические иконки и конечные Tween-анимации. Это визуальная имитация стекла; реальное преломление и локальный blur не реализованы. Показатели и действия расположены по краям, центр занимает только открытое меню. Существующие магазин, награды и перерождения подключены к прежним серверным действиям. Новые донатный и прогрессионный магазины отложены.

Для проверки: подойти к зелёной станции, нажать E или «Тренироваться», накопить 25 монет, купить улучшение, после трёх тренировок забрать ежедневную награду, открыть перерождения. Мобильный вид: Test → Device Simulator → iPhone XR, проверить обе ориентации и открытия меню. Проверка пяти размеров canvas: выполнить `tests/HudStudioQA.lua` целиком в CLIENT Command Bar во время Play; ожидается `HUD_LAYOUT_PASS`. Она временно меняет размеры HUD и восстанавливает их даже при ошибке. Настоящее устройство и сохранение в опубликованной experience требуют отдельной проверки.

## Баланс, ограничения, расширения

Весь баланс находится в Config. Улучшение повышает получаемые силу/монеты; Rebirth даёт +12% к исходному постоянному множителю, до x4 при 25 перерождениях. Требования растут на 8% исходного значения за цикл, рост ограничен после десятого. Реальная скорость зависит от перемещения, покупок и частоты ввода; автоматический расчёт — нижняя оценка при непрерывной игре, не замер человеческой сессии.

Только две станции, один навык и таблица текущего сервера, без глобального OrderedDataStore рейтинга, торговли, PvP, сезонов, питомцев и сложных престижей. Косметика бесплатная; реальные платные предметы отключены до проверки владельцем в Creator Dashboard. За лайки/подписки награды не выдаются: надёжность проверки и допустимость схемы не подтверждены.

AnalyticsEnabled по умолчанию false. При включении в опубликованном плейсе используется подтверждённый [AnalyticsService:LogOnboardingFunnelStepEvent](https://create.roblox.com/docs/reference/engine/classes/AnalyticsService) (вход, первая тренировка, апгрейд, Rebirth), ошибки не блокируют игру. Доставку событий нужно проверить в Dashboard. Возвращаемость/время игры отслеживаются в Creator Analytics, продвижение не гарантируется.

В будущем: выбор специализации после Rebirth, новые зоны, дополнительные косметические предметы, аккуратная монетизация косметики. Они не представлены как готовые функции этого MVP.

DataStore не гарантирует сохранение последних секунд при аварии Roblox/сервера: возможна потеря с момента последнего успешного сохранения. В MVP нет торговли и платных транзакций; для них потребуются отдельные атомарные механизмы выдачи/квитанций. В тестах не включаются привилегированные режимы в production.

### Сетка каталога и лучший состав
Окно яиц/питомцев имеет ширину до 920 px и пять колонок на широком экране; на узком экране сетка адаптируется. В каждом из трёх разделов есть 15 пустых декоративных карточек для проверки шаблона. В «Питомцах» кнопка «Экипировать лучшее» заменяет команду тремя самыми сильными полученными экземплярами (или меньшим числом, если их не хватает), учитывая дубликаты. Выбор делает сервер; четвёртый обычный слот недоступен. Состав сохраняется через существующее поле EquippedPets.
Сетка использует подтверждённый [UIGridLayout](https://create.roblox.com/docs/reference/engine/classes/UIGridLayout). Проверка в свежем Studio Play: tests/CatalogUIStudioQA.client.lua и tests/PetsStudioQA.client.lua, ожидаются CATALOG_UI_PASS и PET_BEST_STUDIO_PASS. Тест питомцев получает команду обычными тренировками и открытиями яиц; не вмешивайтесь во время его выполнения.
### Просмотр и совмещение питомцев
Карточки теперь высотой 216 px, без длинных описаний. У яйца есть «Открыть» и «Редактировать»; у каждого имеющегося экземпляра питомца — «Экипировать/Снять» и «Редактировать». Пустые карточки остаются только декорацией шаблона. Неполученные базовые виды показаны с недоступной экипировкой, улучшенные появляются после крафта.

Нажмите «Редактировать»: каталог переходит с пяти на три колонки, справа появляется увеличенная модель. Перетаскивайте её мышью или пальцем для вращения. В подробностях доступны описание, редкость, множитель и действия. Для совмещения нужны три одинаковых обычных экземпляра: нажмите «Совместить», выберите три карточки слева и подтвердите. Неподходящие карточки затемнены. Получается один улучшенный питомец с коэффициентом ×4 от исходного (x1.10 → x4.40); повторное совмещение улучшенных запрещено.

Расход происходит только после серверной валидации, результат анимируется четыре секунды. Профиль версии 4 принимает старые версии 1–3 без сброса. Улучшенные виды сохраняются в Pets/EquippedPets через существующий DataStore и входят в общий коэффициент и подбор лучших.

В мире и яйца, и тренировка используют E. Нижняя кнопка меняет действие по ближайшему объекту; радиусы не пересекаются и проверяются сервером. Сведения о базе данных из HUD убраны, монеты справа под общим коэффициентом. Меню размывают сцену; стандартные кнопки Roblox не размываются движком вместе с 3D-сценой.

Для проверки в свежем Studio Play запустите по очереди tests/HudStudioQA.lua, tests/CatalogUIStudioQA.client.lua, tests/WorkshopUIStudioQA.client.lua и tests/WorkshopRemoteStudioQA.client.lua. Ждите завершения каждого теста, чтобы их временные изменения canvas не пересекались. Последний зарабатывает питомцев обычными действиями, проверяет крафт, улучшенную экипировку и перерождение; не двигайте персонажа во время его выполнения. Ожидаются HUD_LAYOUT_PASS, CATALOG_UI_PASS, WORKSHOP_UI_PASS и WORKSHOP_REMOTE_PASS. Для визуального теста открытия яйца нажмите E около стойки, затем «Открыть», имея нужные монеты. Отдельно проверьте вращение, три выбора и кнопку подтверждения.

Используются документированные [BlurEffect](https://create.roblox.com/docs/reference/engine/classes/BlurEffect), [SpecialMesh](https://create.roblox.com/docs/reference/engine/classes/SpecialMesh), [ViewportFrame](https://create.roblox.com/docs/reference/engine/classes/ViewportFrame) и [ProximityPrompt](https://create.roblox.com/docs/reference/engine/classes/ProximityPrompt). Облачная версия пока не считается обновлённой: последняя попытка публикации зависла, повторный вход с улучшенными питомцами ещё не проверен.
### Единые пропорции и новая анимация перерождения
HUD использует одну опорную систему 980×620: кнопки, подписи и иконки сохраняют форму и общий масштаб при изменении экрана. Видимого SpawnLocation нет; временная точка задаётся Config.SpawnPosition, сервер помещает туда персонажа при появлении и после смерти. В будущем оформление точки спавна создаётся отдельно под плейс.

Геометрическая стрелка назад соответствует крестику (¾ кнопки). Возврат из подробностей анимирован за те же 0.2 с. Заголовки используют текстовый стиль GlassTypography (GothamBold, тематический цвет и тёмная обводка, без подчёркиваний), центрируются по полной ширине окна; Headings содержит русские/английские подписи, язык определяется устройством. Перерождение показывает старое и новое серверные значения с приближением, 0.2 с старого значения, сменой цвета/текста за 0.1 с и уходом нового коэффициента с затуханием блюра. Проверка: tests/AppearanceStudioQA.client.lua в CLIENT Command Bar, отдельно от tests/HudStudioQA.lua. Ожидаются APPEARANCE_UI_PASS / SPAWN_POSITION_PASS; последний проверяет настоящий повторный спавн после смерти. HudStudioQA проверяет восемь размеров, включая пропорции утверждённого скрина 1224×774.

По новой договорённости важные обновления для отдельного плейтеста публикуются как новая тестовая версия с удалением точно выбранной старой версии. Этот процесс запускается по просьбе пользователя о плейтесте, а не после каждой правки. Исходники и история Git сохраняются.
